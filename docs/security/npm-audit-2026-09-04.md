## Accepted upstream findings

### Expo Router query parsing

```text
expo-router -> query-string@7.1.3 -> decode-uri-component@0.2.2
@react-navigation/native -> @react-navigation/core -> query-string@7.1.3
```

The advisory is `GHSA-vcc3-ghjq-m6fr`. npm proposes installing
`expo-router@5.1.11` or `@react-navigation/native@3.8.4`, both breaking
downgrades from the Expo SDK 55-compatible dependency set. The affected parser
is transitive and no compatible patched release is currently available through
the installed Expo/React Navigation dependency graph.

### Expo iOS project generation

```text
expo -> @expo/config-plugins -> xcode@3.0.1 -> uuid@7.0.3
```

The advisory is `GHSA-w5hq-g745-h8pq`. It concerns UUID v3/v5/v6 calls that
receive an explicit output buffer. This path is part of Expo's local iOS project
configuration tooling. npm proposes downgrading Expo to `46.0.21`; overriding
`uuid` across a major version would also bypass the compatibility contract of
`xcode`.

## Decision

Do not run `npm audit fix --force` and do not force major transitive overrides.
Keep Expo SDK 55 intact, monitor the upstream Expo and React Navigation trees,
and repeat this review when compatible patched releases become available.
