## Findings and source correction

ARS-1 has two linked causes. Concurrent iPhone tests signed out the same synthetic
owners used by Android. The application's default global logout revoked those
Android sessions; local GoTrue history records the logouts and subsequent
`Session not found` responses. QA MMKV and SecureStore file fingerprints remained
unchanged across restart, and diagnostic metadata confirms that the encrypted
session was readable offline. Storage loss or the MMKV key length is not established
as a cause. No key reset, credential rotation or logout-semantics change was made.

NDS-2 is a real synchronization defect exposed by that revocation. An anonymous RLS
collection read returned an empty result with count zero and no query error.
Synchronization treated this as authoritative remote deletion. The retained Android
SQLite contains 5012 pending word deletions: 5000 from the scroll fixture and 12 from
the other synthetic owner. Two additional rows are already synchronized tombstones.
The local server still has 5030 words, including 5028 active rows and two tombstones;
all 5000 scroll words remain active. There are eight server review events, zero
pending Android reviews and zero content commands. An empty review queue therefore
does not establish an empty device write queue.

The local source fix captures and validates the collection snapshot owner, checks
server authentication again after the read, and latches sign-out or owner changes,
including A-B-A. It asserts that guard before and after reconciliation operations.
Three regression scenarios fail before the fix: sign-out during the query, server
revocation without an SDK event, and sign-out followed by the same owner signing
back in. A stable authenticated empty snapshot still reconciles legitimate deletion.
This guard does not promise transaction rollback if authentication changes inside
an already executing SQL mutation. NDS-1's existing tombstone-hydration fix remains.

Two targeted suites pass **127/127** tests. Mobile and test TypeScript checks, scoped
ESLint with zero warnings, and formatting pass. Failed diagnostic attempts, initial
test fixture/type errors and the deliberately failing pre-fix tests are retained;
they are not counted as successful device acceptance. Neither fix is in the signed
build 86 artifacts. Android offline/reconnect acceptance remains open.
