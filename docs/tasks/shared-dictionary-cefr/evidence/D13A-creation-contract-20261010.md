## Change and authority boundary

The [creation contract](../D13A-new-meaning-contract.md) separates a durable original
query/hint resolution request from a minimal creation command referencing the owner's
immutable server resolution. Reviewed sense/source/anchor authority belongs to the
server; spelling, hints and syntactically valid client receipts grant no publication
permission. A new entry has no personal word or expected published head. Existing
shared analysis v2 and old service-only canonical persistence v1 are not fallbacks.

Domain parsers validate exact protocol/nonce/query/hint/receipt fields and reject
client authority injection, mixed resolution evidence, uncharged accepted attempts,
invalid fences/hashes/status/dependencies and publication of anything except the
first validated head of the reserved new entry. Explicit zero-charge existing/busy
responses stay separate from a charged attempt; existing exact references require
following adoption rather than personal creation in this protocol.

Pure journal reducers bind original request/resolution/command/response and active
owner, reserve submission before network dispatch, preserve metadata through JSON
restart and fence terminal/fence/result changes. Unknown provider outcomes cannot
redispatch; only server reconciliation may advance them. Review-required remains
unpublished and terminal for this attempt. Storage/Auth epoch checks and backend
approval are specified prerequisites, not delivered by these pure reducers.

The contract specifies trusted private reviewed identity/evidence, current full_access
or trusted administrator checks, existing10/60 generation and separate independent
judge accounting, concurrency/idempotency, durable dispatch/result quarantine and
atomic initial revision/provenance/head/events. It does not execute these operations.
No provider, private linguistic override, auto collection or native batch completion.
