# Выбор варианта слова при добавлении в словарь

Оба этапа охватывают веб, iOS и Android. Для одного запроса, языка перевода и режима словаря пользователь получает одинаковые варианты в одинаковом порядке на каждой платформе. Полный разбор открывается для проверки перед сохранением выбранной карточки в коллекцию.

## Правила ввода

| Ввод                                                                               | Ожидаемое поведение                                                                   |
| ---------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| `overleden adj`, `overleden adjective`, `overleden (adj)`, `overleden (adjective)` | Запрос прилагательного **overleden**. Перед анализом у поля видна метка **Adjective** |
| `overleden v`, `overleden (verb)`                                                  | Запрос глагола по встретившейся форме, в карточке лемма **overlijden**                |
| `idee noun`, `idee (n)`                                                            | Только существительные. При нескольких артиклях показать варианты                     |
| `snel adv`, `snel (adverb)`                                                        | Запрос наречия                                                                        |
| `de idee`, `idee (de)`                                                             | Одна карточка с артиклем **de**. Аналогично для **het**                               |
| `ik weet het`                                                                      | Выражение целиком. Завершающий артикль считается пометкой только в скобках            |

Сокращённые и полные названия каждой части речи равноправны в обоих форматах. Распознавать отдельный последний токен при наличии слова перед ним. Одиночное `verb` и слова, лишь оканчивающиеся буквами пометки, сохранять целиком. Показывать распознанное ограничение сразу при вводе. При правке очищать устаревший результат и выбор. Артикль в начале многословного выражения сохранять как часть исходного текста; сопоставлять артикль с существительным при поиске словарной записи.

## Общая реализация

- В `packages/domain` разместить общий разбор пометок и правила выбора. В `packages/supabase-contracts` описать запрос и ответ для готового разбора или списка кандидатов. Поиск кандидатов, проверку результата модели и чтение кэша выполнять по общим серверным правилам. Сохранить совместимость с установленными мобильными версиями, которые ожидают один разбор.
- Подключить веб-форму `AddWordWorkflow` и мобильный `AddWordScreen`, включая обычный анализ через `useWordAnalysis` и добавление опубликованного значения через `PublishedMeaningAddWord` на обеих платформах. Сохранить доступные пользователю действия в каждом режиме словаря. Передавать тот же выбор при переходе из списка слов к добавлению отдельной карточки.

## Этап 1. Явное указание варианта

1. Реализовать правила ввода из таблицы одним парсером и покрыть их общими тестовыми примерами. Игнорировать регистр и лишние пробелы в пометках. Артикль в качестве пометки подразумевает существительное. Обработать конфликтующие указания до сетевого запроса. Сохранить значимые скобки в выражениях.
2. Передавать исходную форму и разобранные ограничения отдельно. Параметры API сделать необязательными для действующих клиентов. Применять ограничения при поиске в опубликованном словаре, чтении кэша, генерации и повторном анализе. Проверять часть речи и запрошенный артикль в результате. Если пользователь выбрал конкретную лемму, проверять и её. При несовпадении дать возможность повторить запрос.
3. Разделить исходную форму поиска и каноническую лемму результата в кэше. Проверить текущие ключи и индексы. Старую запись использовать для запроса с пометкой только при подтверждённом совпадении. Исключить перезапись соседнего варианта и попадание ошибочного разбора в коллекцию.
4. Добавить короткую подсказку у поля ввода в вебе, iOS и Android. Сохранять выбранный вариант для повторного анализа и сбрасывать его при изменении запроса. Если запрос с пометкой всё ещё допускает несколько известных вариантов, показать доступный выбор до полного разбора. Для `idee (noun)` это выбор артикля. Сохранять карточку после обычного подтверждения.

## Этап 2. Варианты для слова без пометки

1. Получить короткий список по исходной форме, включая связь формы с леммой. Использовать опубликованные данные и проверенный кэш. Если их недостаточно, запросить у модели только кандидатов. Одна строка старого кэша сама по себе не доказывает однозначность.
2. При одном варианте сразу открыть разбор. При нескольких показать лемму, часть речи, артикль для существительного и короткий перевод на языке пользователя. Для `overleden` показать прилагательное и глагол `overlijden` с указанием введённой формы. Для `idee` показать варианты с артиклями.
3. После выбора использовать готовый разбор подходящего варианта либо запросить один полный разбор. Переиспользовать существующий интерфейс выбора опубликованного значения там, где это возможно. Дедупликацию в коллекции проверять по лемме, части речи и артиклю. Раздельные карточки значений с одинаковыми тремя признаками потребуют отдельного решения по идентификатору значения.
4. Хранить выбор конкретного кандидата до изменения запроса или явной смены варианта. При сетевом сбое дать повторить анализ с тем же выбором. Запоздавший ответ на прежний запрос не должен менять карточку текущего слова. При отсутствии подходящего варианта предложить изменить ввод или снять пометку.

## Проверка

Критерий готовности каждого этапа — прохождение относящихся к нему сценариев в вебе, iOS и Android. Общие примеры покрыть тестами доменной логики и API, ввод и выбор проверить через обычный экран добавления на каждой платформе. Для синхронизации использовать одну учётную запись и одну коллекцию: добавить `overleden (adj)` в вебе и `overleden (verb)` на телефоне, затем сверить обе карточки на всех трёх платформах. Повторить для `de idee` и `het idee`, включая проверку дубликата при повторном добавлении с другого устройства.

| Сценарий                                                                       | Ожидаемый результат                                                                                   |
| ------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------- |
| `overleden (adj)`, включая повторный анализ и наличие старого глагольного кэша | Карточка **overleden** с типом adjective и переводом «умерший, покойный»                              |
| `overleden (verb)`                                                             | Глагольная карточка **overlijden**. Обе карточки можно сохранить в одной коллекции                    |
| `het idee`, `idee (het)`, `idee (de)`                                          | Эквивалентные записи ведут к одной карточке, разные артикли можно сохранить отдельно                  |
| `idee (noun)` при двух известных артиклях                                      | Выбор между **het idee** и **de idee**                                                                |
| `de idee (het)`                                                                | Форма предлагает исправить конфликт до вызова модели                                                  |
| `snel ( ADV )`                                                                 | Разбор наречия с учётом пробелов и регистра                                                           |
| Ввод без пометки после этапа 2                                                 | Для неоднозначного слова сначала короткий выбор. Для однозначного слова сразу разбор                  |
| Повторное сохранение и запрос из прежнего клиента                              | Повторный выбор той же карточки обрабатывается как дубликат. Запрос прежнего формата остаётся рабочим |

Прогнать таблицу правил ввода, тесты домена и контракта, проверки Edge Function с холодным и заполненным кэшем, проверки типов и затронутые тесты веба и мобильного клиента. Проверить интерфейс локально в браузере, на iOS и Android через доступный клиент разработки, симулятор или эмулятор. Для приёмки использовать существующие средства разработки без отдельного профиля QA в EAS.

## Подготовка и выпуск

1. Подготовить изменение в отдельной ветке от актуальной основной ветки. Перед объединением через PR приложить результаты проверок веба, iOS и Android, отдельно указать проверку синхронизации и совместимость старого мобильного клиента.
2. Подготовить совместимый сервер к выходу клиентов. При необходимости изменения схемы сначала применить совместимую миграцию, затем обработчик анализа. Проверить запрос старого формата и запрос новой версии. Сверить релизный коммит, версию приложения, доступные номера iOS/Android и профиль релизной сборки по текущей конфигурации проекта.
3. **Остановиться перед первой командой сборки EAS и написать пользователю:** «Код и проверки готовы. Переключи EAS на личный аккаунт `oldrefery` и напиши, когда переключишь. После этого запущу релизные сборки iOS и Android». Дождаться ответа. Переключение выполняет пользователь.
4. После ответа проверить эффективную учётную запись через `eas whoami` в том же окружении, откуда пойдёт сборка, затем проверить привязку к `@oldrefery/dutch-learning-app`. При несовпадении остановиться и сообщить фактически определённый аккаунт или проект. Токены в вывод не включать.
5. Для согласованного коммита запустить по одной релизной EAS-сборке iOS и Android, сразу в конфигурации для магазина. Отдельные облачные QA-сборки пропустить. Проверить завершение каждой сборки и сообщить ссылки, версию и номера. Веб выпустить через его собственный процесс после проверки совместимости сервера. Готовность мобильных артефактов и фактическую отправку в магазины учитывать раздельно.
